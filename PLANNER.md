# Локальный планировщик поставок

Планировщик — отдельный модуль внутри Mac-приложения. Расчёты, работа со сценариями, SQLite и экспорт выполняются существующим C# / .NET 10 приложением. Go управляет его запуском, а системное окно WKWebView показывает интерфейс. Для работы собранного пакета устанавливать .NET и запускать терминал не нужно.

## Как пользоваться

1. Нажмите иконку SellerStatus в строке меню → «Планировщик». Также раздел есть в боковом меню и в контекстном меню иконки.
2. При первом запуске откроется учебный пример. Задайте параметры и нажмите «Рассчитать план». Даты в примере относятся к началу его модели, а не к сегодняшнему дню.
3. Смотрите потребность по складам, фильтруйте товары, раскрывайте прогноз, учитывайте ожидаемые поступления. Неизвестный остаток и неполная история не выдаются за нули.
4. «Скачать план Excel» / CSV сохраняет отфильтрованный план через системный диалог. JSON переносит исходный сценарий.
5. Для переноса из браузерной версии скачайте там сценарий JSON. Здесь раскройте «Загрузить свой сценарий», выберите этот файл и импортируйте. Перед заменой сохраняется предыдущий сценарий.
6. «Сводка» в верхней панели возвращает мини-панель. Закрытие окна скрывает его; повторное открытие сохраняет текущую страницу. Рассчитанный план и сохранённые копии доступны после полного перезапуска.
7. «Обновить» заново открывает сохранённый расчёт и при необходимости перезапускает локальный процесс. Перед обновлением есть предупреждение о ещё не применённых изменениях.

Тема берётся из общих настроек SellerStatus: системная / светлая / тёмная. Палитра и фокус клавиатуры адаптированы только в Mac-окне. Браузерный интерфейс исходного проекта не меняется.

## Где лежат данные

Оригинальный проект остаётся на прежнем месте. Скрипт подготовки копирует исходники в отдельную рабочую папку, применяет адаптер только к копии и собирает её. Ни `App_Data`, ни браузерные cookies, ни сценарии исходного проекта не переносятся автоматически.

Данные Mac-версии: `~/Library/Application Support/SellerStatusMac/Planner/`. Там находятся SQLite, ключи защиты данных и постоянный идентификатор рабочего пространства. Это отдельное хранилище; переносить нужные сценарии следует через JSON. Секрет сессии существует только во время запуска. Сценарии не включаются в архив приложения.

Исходники учебного проекта и подготовленный .NET runtime игнорируются Git в `.local/`. В публичный репозиторий входят только адаптер, оболочка и скрипты интеграции. Локальная сборка `.app` включает бинарную копию учебного модуля; она не публикуется автоматически в GitHub Releases.

## Подготовить модуль

Нужен .NET SDK 10 для сборки, Node.js, Go и инструменты Apple из README. Из корня Mac-проекта:

```sh
python3 scripts/prepare-planner.py --source /absolute/path/to/supply-planner
./scripts/build-macos.sh
```

Скрипт запускает тесты C# в копии перед self-contained публикацией. `--work-dir` позволяет вынести временные исходники и NuGet-кеш из `.local/`; `--skip-tests` предназначен для повторной сборки после уже выполненных проверок.

Вызовы `dotnet` используют собственные `DOTNET_CLI_HOME` и `NUGET_PACKAGES`. Оригинальный кеш при наличии копируется, оригинальные файлы не изменяются. Рабочая папка не может совпадать с исходной или находиться внутри неё. Неизвестная структура bootstrap-кода останавливает сборку.

Без подготовленного `.local/planner` оболочка собирается отдельно, а попытка открыть планировщик показывает ошибку с возможностью повтора.

Текущая полная сборка — Apple Silicon, macOS 14+. Минимальная версия повышается при включении .NET 10; см. [поддерживаемые версии macOS](https://learn.microsoft.com/en-us/dotnet/core/install/macos#supported-versions). Intel и старые macOS физически не проверены.

## Границы локального процесса

- Запускается при первом открытии; одновременные открытия объединяются.
- Перезагрузка конфигурации по изменениям файлов выключена: готовый пакет не должен создавать наблюдатели за синхронизируемой папкой Documents.
- Слушает только `127.0.0.1` на свободном порту. Не использует и не останавливает браузерный сервер на 5099.
- Доступ защищён случайным секретом запуска, HttpOnly / SameSite=Strict cookie, проверкой Host и Origin. Для изменения данных дополнительно работает исходная CSRF-защита Razor Pages.
- Go принимает адрес готовности только из stdout собственного дочернего процесса и проверяет `/healthz` с секретом.
- Секрет не попадает в URL, React, localStorage, Git или диагностический лог. Браузерный мост Wails не подключён к окну C#; переходы и перенаправления загрузок ограничены локальным источником.
- Закрытие окна оставляет процесс для быстрого открытия. Выход из приложения закрывает stdin; C# останавливается и при аварийном завершении родителя. Предусмотрено принудительное завершение только собственного процесса после ожидания.
- При неудачном старте ограниченный диагностический хвост записывается в `startup-error.log` в локальной папке Planner. Успешный старт убирает прежний лог.

Сводка магазина пока использует демоданные. Она не переносится в расчёт автоматически: одного среднего спроса недостаточно для полноценной дневной истории планировщика. WB и реальный сервер SellerStatus эта интеграция не опрашивает.

## Воспроизвести проверки

```sh
python3 scripts/test-planner.py
python3 scripts/test-planner.py --runtime 'build/SellerStatus Mac.app/Contents/Resources/planner'
SELLERSTATUS_TEST_RUNTIME="$PWD/.local/planner/SupplyPlanner.Web" go test -race .
```

HTTP-проверка использует временную SQLite и проверяет доступ, CSRF, расчёт, JSON/CSV/Excel, импорт, сохранённые копии, повторный запуск, изоляцию рабочих пространств и остановку при закрытии родительского канала. Она не меняет пользовательские сценарии.
