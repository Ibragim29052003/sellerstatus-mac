3. Добавить ограниченные повторы только для временных ошибок; для 429 соблюдать Retry-After. Не повторять автоматически 401/403 и ошибки контракта. Избегать отдельных WB-запросов при каждом клике: получать агрегированный снимок SellerStatus, кешировать и объединять одинаковые запросы.

## Что работает с данными сейчас

Используется только детерминированный демоисточник. RTK Query кеширует снимки по периоду и сценарию. `currentData` отделяет снимки разных запросов. Есть начальная загрузка, повторное обновление, ручной повтор после ошибки, пустой кабинет, неполная себестоимость и устаревшие остатки. Денежные показатели и складские правила проверяются тестами.

Автоматические повторы временных серверных ошибок, реальная авторизация, постоянный кеш снимков, работа без сети и живой WB/SellerStatus пока не реализованы. Новости и реальные уведомления — отдельный последующий объём, они не входят в обещание завершить интерфейс завтра.

## Границы совместимости

Текущая сборка: Apple Silicon, минимальная заявленная macOS 13. На M3 Max не требуется отдельный код. Вырез необязателен благодаря расчёту safe area, но это не подтверждает работу на каждом Mac: физические Intel, старые macOS и несколько мониторов ещё не проверены.
